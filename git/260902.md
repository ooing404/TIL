# Git 실습 정리

> 2026.09.02 수업 필기

---

## 1. Git 저장소 생성

```bash
git init
```

현재 폴더를 Git 저장소로 초기화한다.

`git init` 실행 후 폴더에서 **숨김 파일 보기**를 활성화하면 `.git` 폴더가 생성된 것을 확인할 수 있다.

`.git` 폴더에는 Git이 버전을 관리하기 위해 필요한 정보가 저장된다.

---

## 2. 파일 Staging

### 특정 파일 추가

```bash
git add hello.txt
```

특정 파일을 Staging Area에 추가한다.

### 현재 폴더의 모든 변경사항 추가

```bash
git add .
```

`.`은 현재 디렉터리를 의미한다.

---

## 3. Git 상태 확인

```bash
git status
```

현재 Git 저장소의 상태를 확인한다.

- 수정된 파일
- Staging된 파일
- 아직 Git이 추적하지 않는 파일

등을 확인할 수 있다.

---

## 4. Commit

```bash
git commit -m "커밋 메시지"
```

Staging Area에 올라간 변경사항을 하나의 버전으로 저장한다.

예시:

```bash
git commit -m "hello.txt 추가"
```

---

## 5. Commit 기록 확인

### 전체 로그 확인

```bash
git log
```

### 간단하게 한 줄로 확인

```bash
git log --oneline
```

예시:

```text
2fed398 hello.txt 수정
38abc12 hello.txt 생성
```

앞에 있는 `2fed398` 같은 값은 **Commit ID(Hash)의 일부**이다.

---

## 6. 특정 Commit 되돌리기

```bash
git revert 2fed398
```

특정 Commit에서 발생한 변경사항을 되돌린다.

여기서 `2fed398`은

```bash
git log --oneline
```

으로 확인한 Commit ID이다.

> `revert`는 기존 Commit 기록을 삭제하는 것이 아니라  
> 해당 변경사항을 취소하는 **새로운 Commit을 생성**한다.

# GitHub 원격 저장소 연결

## 7. Remote 저장소 등록

```bash
git remote add origin https://github.com/ooing404/git-practice-sekim.git
```

현재 로컬 Git 저장소에 GitHub 원격 저장소를 연결한다.

- `origin` : 원격 저장소의 별칭
- URL : 연결할 GitHub Repository 주소

---

## 8. Remote 확인

```bash
git remote -v
```

현재 연결된 원격 저장소 주소를 확인한다.

---

## 9. GitHub에 Push

처음 Push할 때:

```bash
git push -u origin main
```

`-u`는 upstream 설정 옵션이다.

처음 한 번 연결해두면 이후에는 간단하게

```bash
git push
```

만 실행해도 된다.

---

## 10. GitHub에서 Pull

```bash
git pull origin main
```

원격 저장소의 `main` 브랜치 내용을 로컬로 가져오고 병합한다.

---

# Branch

## 11. 새로운 Branch 생성

```bash
git branch feature/greeting
```

`feature/greeting`이라는 새로운 브랜치를 생성한다.

---

## 12. Branch 목록 확인

```bash
git branch
```

현재 존재하는 브랜치를 확인한다.

현재 위치한 브랜치 앞에는 `*`가 표시된다.

예시:

```text
* main
  feature/greeting
```

---

## 13. Branch 이동

```bash
git switch feature/greeting
```

`feature/greeting` 브랜치로 이동한다.

다시 main으로 이동:

```bash
git switch main
```

---

## 14. Branch 생성 + 이동

```bash
git switch -c feature/conflict
```

새로운 `feature/conflict` 브랜치를 만들면서 동시에 해당 브랜치로 이동한다.

즉,

```bash
git branch feature/conflict
git switch feature/conflict
```

를 한 번에 하는 것과 비슷하다.

---

# Merge

## 15. Branch 병합

먼저 main 브랜치로 이동한다.

```bash
git switch main
```

그 다음:

```bash
git merge feature/greeting
```

`feature/greeting` 브랜치의 변경사항을 현재 위치한 `main` 브랜치에 병합한다.

> 중요: `git merge feature/greeting`은  
> **main 브랜치에서 실행한다.**

---

# Merge Conflict

## 16. 충돌 실습

브랜치 생성:

```bash
git switch -c feature/conflict
```

브랜치에서 파일을 수정하고 Commit한다.

이후 main으로 이동:

```bash
git switch main
```

main에서도 같은 부분을 다르게 수정한다.

병합:

```bash
git merge feature/conflict
```

같은 부분을 서로 다르게 수정했다면 **Merge Conflict(충돌)**가 발생할 수 있다.

---

## 17. 충돌 표시

충돌이 발생하면 파일에 다음과 같이 표시될 수 있다.

```text
<<<<<<< HEAD
메인에서 hello 수정!
=======
브랜치에서 수정함!
>>>>>>> feature/conflict

추가한 내용입니다.
```

의미:

- `<<<<<<< HEAD` 아래 → 현재 브랜치의 내용
- `=======` → 두 내용을 구분
- `>>>>>>> feature/conflict` 위 → 병합하려는 브랜치의 내용

원하는 내용만 남도록 직접 수정하고 충돌 표시를 제거한다.

---

## 18. 충돌 해결 후 Commit

충돌을 직접 수정한 후:

```bash
git add .
```

그리고:

```bash
git commit -m "충돌 해결"
```

충돌 해결 내용을 Commit한다.

# 오늘 배운 전체 흐름

## 기본 Git 작업

```text
파일 수정
   ↓
git add .
   ↓
git commit -m "메시지"
   ↓
git push
```

## Branch 작업

```text
main
 ↓
새 Branch 생성
 ↓
Branch에서 작업
 ↓
add + commit
 ↓
main으로 이동
 ↓
merge
```

## 자주 사용한 명령어

| 명령어 | 의미 |
|---|---|
| `git init` | Git 저장소 생성 |
| `git status` | 현재 상태 확인 |
| `git add .` | 변경사항 Staging |
| `git commit -m "메시지"` | Commit 생성 |
| `git log` | Commit 기록 확인 |
| `git log --oneline` | Commit 기록 간단히 확인 |
| `git revert <commit>` | 특정 Commit의 변경사항 되돌리기 |
| `git remote -v` | 원격 저장소 확인 |
| `git push` | 원격 저장소로 업로드 |
| `git pull` | 원격 저장소 변경사항 가져오기 |
| `git branch` | Branch 확인 |
| `git switch <branch>` | Branch 이동 |
| `git switch -c <branch>` | Branch 생성 + 이동 |
| `git merge <branch>` | Branch 병합 |
| `git clone <URL>` | 원격 저장소 복제 |
